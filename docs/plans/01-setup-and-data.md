# Этап 1. Каркас проекта и подготовка данных

**Срок:** 20.11–24.11.2026

## Цель

Создать каркас проекта и получить очищенный объединённый справочник. По результатам анализа данных зафиксировать единственный шаблон наименования трубы, по которому на этапе 5 будут генерироваться новые конфигурации.

## Пункты ТЗ

- §4.1: источник данных, поля «Полное наименование МТР» и «Замены», 1794 записи, 701 уникальная пара.
- §4.2, разовая подготовка, п. 1: объединение справочников и удаление дубликатов.
- §6 п. 2: считывание наименований и вариантов замен.
- §6, последний абзац: сохранять все уникальные пары «Наименование – Замены».
- §7 п. 4: стек технологий.

## Входы

- `data/2022год_НГП.xlsx`, `data/2023год_НГП.xlsx` (загружены).
- Предварительный анализ: [../data-analysis.md](../data-analysis.md).

## Definition of Done

- `python scripts/prepare_data.py` выполняется без ошибок и выдаёт справочник с уникальными парами.
- Расхождение с числами из ТЗ отсутствует или объяснено.
- Шаблон наименования записан и подтверждён примерами из данных.

## Риски

| Риск | Что делаем |
|---|---|
| Пользователь загрузит через веб файл с другой структурой | Понятная ошибка «не найдены столбцы …» вместо падения |
| Разбивка «Замен» на варианты где-то ошибётся | Храним и исходную строку; в интерфейсе можно показать её как есть |
| Заказчик не согласует трактовку «марка стали / класс прочности» | Тогда метрику извлечения считаем только по запросам, где марка стали реально указана, и явно пишем это в отчёте |
