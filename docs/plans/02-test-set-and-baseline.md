# Этап 2. Тестовая выборка, скрипт оценки и TF-IDF baseline

**Срок:** 25.11–28.11.2026

## Цель

До настройки алгоритма заморозить тестовую выборку и написать скрипт оценки. Получить первую точку отсчёта на TF-IDF, с которой потом сравнивается гибридный алгоритм.

## Почему этап идёт вторым

ТЗ требует, чтобы тестовая выборка не использовалась при настройке алгоритма (§4.2, §10). Если собирать её после подбора регулярных выражений и весов, запросы невольно подстроятся под алгоритм, и метрика будет завышена. Поэтому выборку фиксируем раньше, чем пишем извлечение и ранжирование.

## Пункты ТЗ

- §3.2: Hit Rate@3, точность извлечения, время обработки.
- §4.2, п. 5: 20 запросов, из них не менее 5 с новыми комбинациями параметров.
- §4.2: запросы строятся из реальных наименований с перестановкой слов, сокращениями и небольшими опечатками.
- §5 п. 1, §8 п. 4: TF-IDF и косинусное сходство как baseline.
- §8 п. 10, §10: оценка на фиксированной выборке с заранее известными ответами.

## Задачи

- [x] Формат `data/test/test_queries.json`. Для каждого запроса:
  - `id`, `query` — текст запроса;
  - `kind`: `existing` (позиция есть в справочнике) или `new_combination`;
  - `expected_names` — эталонные наименования (для `existing`). Решили хранить наименования, а не `item_id`: идентификаторы зависят от порядка строк в файлах, а наименования стабильны. В список входят и варианты, отличающиеся только «или эквивалент» или примечанием об ударной вязкости;
  - `expected_spec` — ожидаемые тип трубы, диаметр, толщина стенки и «марка стали / класс прочности» (для всех запросов);
  - `expected_group` — группа для шаблона генерации (для `new_combination`);
  - `distortions` — какие искажения применены (для отчёта).

## Риски

| Риск | Что делаем |
|---|---|
| У одного запроса несколько правильных ответов (дубли, замены) | `expected_names` — список, попадание любого из них в top-3 считается успехом |
| Baseline уже даёт HR@3 = 93%, разницу с гибридом по этой метрике не видно | Сравниваем ещё по HR@1, MRR и доле top-1 с несовпадающими параметрами; выборку под baseline не меняем |
| 20 запросов — маленькая выборка, метрика скачет | Отдельно отслеживаем результат на dev-выборке; в отчёте указываем, что 1 запрос = 5 п.п. |
